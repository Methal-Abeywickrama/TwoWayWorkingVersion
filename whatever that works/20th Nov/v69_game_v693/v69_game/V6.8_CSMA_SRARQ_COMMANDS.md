# v6.8: CSMA/CA + Selective-Repeat ARQ (TXOP burst, Block ACK)

| file | what it is |
|---|---|
| `v6.8_csma_srarq.grc` | v6.5_csma_mono with the CSMA block replaced by the v6.7 DCF MAC + selective-repeat ARQ. No debug logging. GRC generates `csma_srarq.py`. |
| `v6.8_csma_srarq_stress.grc` | The same, plus the START/READY stress test, 21 stage probes and the two log files per PC. GRC generates `csma_srarq_stress.py`. |
| `analyze_stress.py` | New section "MAC + SR-ARQ": bursts, Block ACK bitmaps, window use, and why each frame had to be sent again (frame lost vs Block ACK lost). |

Both PCs must run v6.8. The MAC header changed (frame control `1011…`), so v6.7 and v6.8 nodes do not understand each other.

---

## 1. Run (plain version)

**PC A (ID 0)**
```bash
export CDP_MY_ID=0 CDP_DEST=1
export CDP_ARQ_M=4 CDP_ARQ_N=16
gnuradio-companion v6.8_csma_srarq.grc &
```
**PC B (ID 1)**
```bash
export CDP_MY_ID=1 CDP_DEST=0
export CDP_ARQ_M=4 CDP_ARQ_N=16
gnuradio-companion v6.8_csma_srarq.grc &
```
Type in the TX Message box as before: `@1 text`, `@all text`, or plain text to the default destination. Every 10 s the console prints:
```
[MAC] ... | bursts by size {1: 15, 3: 77, 4: 16}, Block ACKs received 98 (late 0), timeouts 22, CW 15 | Block ACKs sent 108, NAV set 0x
[ARQ] frames sent 374 (retransmissions 95), acknowledged 279, dropped after 7 retries 0, queue drops 0 | received 279 new + 24 duplicates, given up 0 | to 1: WS 279, in window 0/16, backlog 0 | delay median 303 ms, Block ACK round trip median 48.6 ms (timeout 70)
```
Received text appears as `[RX RECEIVED] SN 12 from ID 1 to ID 0: ...`, in order.

## 3. Parameters (environment; `MAC_*` / `ARQ_*` variables in the flowgraph)

| env variable | default | meaning |
|---|---|---|
| `CDP_ARQ_M` | `4` | **M**: max frames per TXOP burst = number of bits in the Block ACK bitmap (1–64) |
| `CDP_ARQ_N` | `16` | **N**: selective-repeat window (sender window and receiver reorder buffer), N ≥ M |
| `CDP_MAC_TXOP` | `0.25` | TXOP limit: max airtime of one burst in s (always at least 1 frame) |
| `CDP_MAC_BA_TO` | `0.070` | Block ACK timeout in s, counted from the end of the burst on air |
| `CDP_MAC_RETRY` | `7` | retransmissions per frame before it is dropped (802.11 short retry limit) |
| `CDP_MAC_P` | `0.5` | p-persistence: chance to go ahead per idle 2 ms slot (flowgraph default; v6.9.1: 0.2, v6.9: 0.04) |
| `CDP_MAC_SLOT` | `0.002` | slot time (s) |
| `CDP_MAC_SIFS` | `0.001` | SIFS (s): the Block ACK is sent this long after the burst ends |
| `CDP_MAC_TURN` | `0.025` | turnaround on this SDR (frame end on air → reply on air); sets DIFS and the NAV duration |
| `CDP_MAC_DIFS` | `0` | DIFS (s); `0` = SIFS + turnaround + 2·slot = 30 ms |
| `CDP_MAC_CWMIN` / `CDP_MAC_CWMAX` | `15` / `1023` | contention window limits |
| `CDP_MAC_KMAX` | `5` | max backoff stage K (CW 15, 31, 63, 127, 255, 511) |
| `CDP_MAC_PRE1` | `256` (QPSK `512`) | v6.9.2: preamble (bytes) of the **first frame of every transmission** (first DATA frame of a burst, every Block ACK). `0` = off |
| `CDP_MAC_PRE_IN` | `64` (QPSK `128`) | v6.9.3: preamble (bytes) of **frames 2..M of a burst** (the receiver is already locked); these frames also get no postamble, the last frame pads the whole burst. `0` = no preamble, `128`+ = off |
| `CDP_MOD` | `bpsk` | v6.9.3: `bpsk` or `qpsk` (login screen). The preamble defaults double at QPSK so they last as long in time |
| `CDP_MAC_DUP_AFTER` | `4` | v6.9.2: a frame that has been retried this often is sent **twice** in its burst (second copy at the end). `0` = off |
| `CDP_MAC_WBA` | `1` | v6.9.2: Block ACK with a bitmap of the receiver's **whole window** (SSN + 16 bits) instead of the 4 burst positions. `0` = send the v6.9 format (both are always understood). Both nodes need v6.9.2 |

The frame airtime formula uses the framer's settings, so the MAC takes `preamble_len`, `FEC`, `BUFFER_SIZE` and `max_payload_len` from the flowgraph. If you change the framer, these follow automatically. If the console ever prints `frame length formula off`, they do not match.

## 4. Tuning

| what you see | change |
|---|---|
| Block ACK round trip close to the timeout, or many `ba_*` losses in the report | raise `CDP_MAC_BA_TO` (round trip max + 15 ms) |
| `in window 16/16` with a growing backlog | the receiver is missing an early frame. Raise `CDP_ARQ_N` so later frames can keep flowing |
| low Block ACK bitmap success at the later burst positions (#2, #3 …) | the RX chain loses sync during long bursts. Lower `CDP_ARQ_M` or `CDP_MAC_TXOP` |
| many `data_collision` | raise `CDP_MAC_SLOT` or lower `CDP_MAC_P` (as in v6.7) |
| throughput is too low and the channel is clean | raise `CDP_ARQ_M` (one contention and one Block ACK per M frames) |
