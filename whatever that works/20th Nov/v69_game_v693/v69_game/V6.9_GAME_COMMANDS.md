# v6.9.1 + Radio Arena v4: all commands

**The v6.9.1 stack is unchanged up to the ARQ**, with the changes you asked for:
- **TX attenuation while sending starts at 0 dB.** In `v6.9_cdp_link.grc` the default of `CDP_TX_ATT` changed from 20 to 0.
- **The `cdp_daemon.py` login only asks for this PC's node number.** The other nodes are discovered on the link.
- **The flowgraph's four per-sample Python blocks run their inner loops in C++** (`cdp_fast.cpp`). This gives the same
  results with less CPU. Without a compiler they run the original Python code.

`README.md` and `LOGS.md` describe these changes.

- `cdp_sock.py` and `cdp_logsum.py` are your files, byte for byte.
- The game sits on top of the bridge's datagram service.
- New: `cdp_game.py`, `game/`, `tools/`, and for the chat app and the flowgraph `cdp_crypto.py`, `cdp_voice.py`, `cdp_metrics.py`, `cdp_fast.py` + `cdp_fast.cpp`.

**Update every PC:** Radio Arena v4 (elevation, sniper, knife, healing) doesn't play with the earlier v3 game. Its packets use new type numbers, so the two ignore each other, and the lobby says "node N runs an older Radio Arena".

Put the **whole folder** on every PC (the same files on all of them). `cdp_game.py` and `game/` must stay next to `cdp_daemon.py`, because the daemon finds `cdp_game.py` there and shows **🎮 Start game**.

## One-time install (Fedora)

```bash
sudo dnf install python3-pygame python3-pyopengl gcc-c++
```
`gcc-c++` builds the flowgraph's C++ kernels. Check them once on each PC:
```bash
cd ~/v69_game
python3 cdp_fast.py        # builds (~2 s), self-tests and compares the speed with the NumPy code
```
It should print `C++ kernels built/loaded and self-tested`. When the flowgraph starts, its console shows a line like
`[FAST] MAC carrier sense: C++ kernel on` for each of the four blocks. To run without them: `export CDP_FAST=0`.
If dnf can't download on the university Wi-Fi, log in at `wlan.uom.lk` first. GNU Radio and PyQt5 are already there from v6.9.

## 1. Play (the normal way: through the daemon)

**PC A: node 0, methalabeywickrama**
```bash
cd ~/v69_game
export CDP_MY_ID=0            # pre-fills this PC's node number at login (optional)
export CDP_TX_ATT=0           # TX attenuation while sending: 0 dB (full power)
python3 cdp_daemon.py
```
**PC B: node 1, maduwage**
```bash
cd ~/v69_game
export CDP_MY_ID=1
export CDP_TX_ATT=0
python3 cdp_daemon.py
```
`export CDP_TX_ATT=0` is the default now. It's written out because a value exported earlier in the same terminal (or in `~/.bashrc`), such as 32 or 20, would otherwise still win. Check it with `echo $CDP_TX_ATT`. The GRC slider "TX attenuation while sending" still changes it while running.
**More PCs:** run the same commands with their own number (`export CDP_MY_ID=2`, `3`, …). Every PC needs a different one: if two PCs share a number, the chat window says so in red.

Then on every PC:
1. **Login screen: only your node number.** It's pre-filled from `CDP_MY_ID` (else the number used last time on that PC). Check it and press **Log in**. There are no opponents to enter any more.
2. GNU Radio Companion opens `v6.9_cdp_link.grc`. **Press ▶ Run (F6)**. The chat window shows *connected*.
3. **The other nodes appear by themselves**:
   - Each daemon broadcasts a short presence message every 5 s (`CDP_PRESENCE_S`) and answers a new node at once.
   - Any node that is heard gets its own chat (● online, ○ away). Until then the window says "No other node heard yet".
   - A PC that joins later shows up on everyone's list within a few seconds.
4. Press **🎮 Start game** in the chat window's sidebar. The game opens on its main menu.
   - The menu header shows `node N · nodes heard … · v6.9 radio, udp 5200/5201`.
5. Click **Play online**. The lobby lists every node that runs the game, with its status, link and ping. Nodes the chat has heard but that aren't in the game yet are listed as *not heard*.
6. Click **Enter arena** on every PC.
   - The first players elect a host: the lowest ping, or random if chosen in the menu.
   - Players who click later join the running arena.

**Controls:**

| key | action |
|---|---|
| W A S D, mouse | move, look |
| left mouse | shoot / slash (sniper: one click per shot) |
| right mouse (hold) | sniper scope |
| 1 / 2 / 3 | rifle / sniper / knife |
| Q / mouse wheel | last weapon / switch |
| H | heal: a medkit gives +50 HP over 3 s, then 8 s until the next. Firing stops it. |
| R | reload |
| Space / Shift | jump / sprint |
| TAB | scores |
| Esc | pause menu |
| F10 | quit the game |

**The arena:**
- **Buildings:** two you can climb by their stairs (3.0 m west, 2.0 m south-east).
- **Crates:** a 1.0 m crate can be jumped onto.
- **Medkits:** white boxes with a red cross, on 6 spots (one on each roof). Each eliminated player drops one too.

Details and numbers are in `game/GAME.md`.

**Closing:**
- **Quit game** (pause menu or main menu) closes only the game. The chat and the radio keep running, and **🎮 Start game** opens the game again.
- **Close everything** (pause menu or main menu) stops the game, the flowgraph, GRC and the chat. It sends `SHUTDOWN` to the daemon's control port, the same as `python3 cdp_daemon.py --shutdown`.
- The chat's **⏻ Close everything** also closes the game.

## Chat: encryption, voice, dashboard

**🔒 Encryption** is on by default.
- **Keys:** each PC has a key pair. The public key is g^x mod p over a 2048-bit prime, and it travels in the presence messages.
- **Messages:** text, files and voice are encrypted per node.
- **Check the keys once:** "👥 Nodes in this session" shows each node's key fingerprint. It should match what the other PC shows as "my key".
- **Switching it off:** the sidebar button turns it off and on; `export CDP_ENCRYPT=0` starts with it off.

**🎙 Voice:**
- **Live:** click **🎙 Talk** below the message box to go on air to the open chat's node. It stays on (the line above shows ON AIR and the time) until you click **⏹ Stop talking**.
- **Voice message:** **🎤 Voice msg** records one; click again to send it as a reliable chat item.
- **Audio tools (one-time):**
```bash
sudo dnf install pulseaudio-utils          # parec / pacat; or alsa-utils (arecord / aplay); or: pip install sounddevice
```

**📊 Performance dashboard:** opens live charts of this link in the browser. For an old session: `python3 cdp_metrics.py debug/<session>`.
- **If a yellow note says the flowgraph writes to another folder:** a GRC from an earlier start is still running. The dashboard follows it anyway. For clean logs, close every GRC window, then press ▶ Run in the one the chat app opens.
- **The "Chat app" chart** shows the messages and files you send (delivered) and receive. It moves even if no flowgraph logs are found.
- **If something breaks,** the error text appears in red at the top of the page: send it to me.

The daemon now owns datagram port 5201: it keeps the voice and passes everything else to the game on 5202. Start the game from the chat window (🎮), not by hand, while the daemon runs.

## 2. Game settings (optional)

Set these **before** `python3 cdp_daemon.py`. The game inherits them from the daemon. Each one is only the start value: the main menu can still change it.

| variable | default | meaning |
|---|---|---|
| `CDP_GAME_ARQ` | `0` (menu: "Datagrams (ARQ bypass)") | `1` sends the inputs to the host as reliable messages (SR-ARQ). Only for 2 players. See `GAME_V69.md`. |
| `CDP_GAME_RATE` | 5 | packets/s per player (0.5 – 10) |
| `CDP_GAME_MAX` | 4 | max players in the arena (2 – 8) |
| `CDP_GAME_LAG` | 1.0 | lag limit in s: older shots and moves are rejected by the host |
| `CDP_GAME_ARGS` | – | extra game arguments, e.g. `"--fullscreen"` or `"--size 1920x1080 --sens 0.1"` |

Recommended:
- **2 players** (the two PCs): the defaults. Datagrams at 5/s; reliable inputs (`CDP_GAME_ARQ=1`) also work.
- **3–4 players:** datagrams (the default) at 5/s. Never `CDP_GAME_ARQ=1` here: reliable inputs pile up in the bridge's queue. With 4 players, `CDP_GAME_LAG=1.5` is gentler on slow links.

Example (PC A, 3 players, fullscreen):
```bash
cd ~/v69_game
export CDP_MY_ID=0 CDP_TX_ATT=0 CDP_GAME_RATE=5 CDP_GAME_MAX=3 CDP_GAME_ARGS="--fullscreen"
python3 cdp_daemon.py
```

The menu values are saved in `~/.cdp_game_v69.json`, separately from the v6.8 game's `~/.cdp_game.json`. A value from the environment wins whenever it differs from the one given last time.

The v6.9.1 link settings (`CDP_SAMP_RATE`, `CDP_UDP_QUEUE`, `CDP_MAC_P`, `CDP_MAC_CWMAX`, `CDP_ARQ_M`, `CDP_ARQ_N`, …) work exactly as in `README.md`.

## 5. Logs

**The dashboard's data** comes from the flowgraph's Session Logger. Right after ▶ Run its console shows
`[LOG] performance logs -> /home/…/v69_game/debug/<session>`. No such line means the logger isn't running (see README).

**Where the flowgraph's console output goes** (`[MAC]`, `[RX]`, `[ARQ]`, `[FAST]` … lines):
- **GRC mode** (the default at login): the console panel at the bottom of the GRC window.
- **"Run the flowgraph directly (no GRC window)":** the terminal where `python3 cdp_daemon.py` runs, with the
  daemon's own lines. The login remembers that choice; untick it to get the GRC window back.
- **Both modes:** a copy in `debug/<session>/` (`flowgraph.log`, or `grc.log` for GRC's own messages). Follow it with
  `tail -f debug/<session>/flowgraph.log`.


The daemon writes the game's output to `debug/<session>/game.log`, next to the flowgraph's CSVs. Every 5 s it gets a line with:
- role, host, the rate actually sent and the radio queueing delay
- ping to the host and the game counters

The datagrams themselves appear in `udp.csv` of the session, as for every UDP user (see `LOGS.md`).

Summarise as before:
```bash
python3 cdp_logsum.py debug/<session_PC_A> <session_PC_B> -o summary.md
```
